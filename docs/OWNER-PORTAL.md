# لوحة المالك

توجد لوحة إدارة المالك في `/owner.html`. تستخدم رابط دخول يرسله Supabase إلى البريد؛ لا تحتوي على كلمة مرور مشتركة ولا تحفظ جلسة الدخول في تخزين المتصفح.

## الوصول

- يرسل زر «طلب تفعيل حساب المالك» طلبًا إلى Edge Function `clinic-owner-bootstrap`. يرسل الخادم دعوة فقط للبريد الموجود في قائمة المالكين المسموح بها.
- بعد فتح رابط البريد، تتحقق `clinic-platform-admin` من JWT وتربطه بحساب مالك المنصة.
- كل عمليات الإدارة تمر عبر Edge Function وتتحقق من دور المالك على الخادم. لا يصل مفتاح الخدمة إلى المتصفح.
- دعوة الدكتور تفتح `/clinic/index.html?clinic=<slug>&portal=doctor`. التطبيق يقرأ جلسة الدعوة من رابط Supabase في الذاكرة ويعرض مساحة الدكتور بعد التحقق من العضوية.

## ما يديره المالك

إنشاء عيادة وبريد الدكتور، كتابة `slug` يدويًا، تعديل القالب واللون والصورة والنصوص والعنوان والخدمات والأسعار والمدد والأولويات، مراجعة طلبات التعديل، تحديد نهاية الاشتراك، وإيقاف العيادة أو إعادة تفعيلها. رفع الصور يقتصر على JPG وPNG وWebP حتى 5 ميجابايت، ويحفظ الملفات في مجلد العيادة داخل Supabase Storage.

روابط المريض والدكتور تستخدم نطاق المنصة الحالي، مع `?clinic=<slug>`. الرابط مثل `Dr-Ahmed.com` يحتاج شراء نطاق مستقل، ضبط DNS، ثم التحقق وإضافة النطاق إلى إعدادات الاستضافة وSupabase؛ كتابة slug وحدها لا تشتري أو تربط نطاقًا.

## إعداد قاعدة البيانات

المشروع الحالي لديه migrations إضافية مطبقة في Supabase لإدارة المالك والاشتراكات والتخصيص وتخزين الصور. بعض هذه migrations لم تُزامن بعد إلى مجلد `supabase/migrations` في المستودع. يلزم إضافة مصادرها قبل إنشاء نسخة إنتاجية جديدة من الصفر؛ لا تعِد تشغيلها فوق قاعدة البيانات الحالية.
